# 缺陷修复：用量统计失真、重复续写、以及 4 项遗留缺陷

Status: implemented
Scope: 只修代码缺陷（计量、并发去重、上传安全、回溯上限、SSE 节点名、响应字段），不含数据清理与文档重写

## Outcome
1. `/api/usage` 与 `src/logs/tokens.log` 里的 token 数反映**单次调用的真实用量**（不再出现 169 万 input 这种数字），并能看到缓存命中与推理 token。
2. 一次「续写」只会产生**一个**新会话：连点无效。
3. 上传参考文件时，文件名里的路径部分被丢弃，无法写到 `knowledge_base/` 之外。
4. 「回退」按**实际回溯次数**限制（默认 5 次），不再因为剧情段数变多而失效。
5. SSE 的 `node_start/node_end/token` 事件归属于**真实的图节点**（supervisor/world_builder/story_driver/critic/review_gate/integrator），不再被嵌套 runnable 覆盖。
6. 刷新页面后顶部的「段落」计数与后端一致。

## Why
- 用量统计失真（流式分片 usage 被求和）导致省 token 效果无法评估，也会误判成本。
- 昨晚真实运行中 4 秒内触发了 6 次续写，产生 6 个同样的会话并白花 6 次生成。
- 文件名未净化可写到项目目录之外；回溯上限写错导致长会话无法回退；SSE 节点名错误会让前端状态提示误导；段落计数错误影响判断。

## In scope
- token 计量：单次调用的 input/output/cache_read/reasoning 取值正确。
- 续写/新建等侧栏操作的重复提交防护（前端禁用 + 后端并发闸门）。
- 上传文件名净化与目标路径包含性校验。
- 回溯次数上限语义修正。
- SSE 事件归属到图节点。
- `SessionResponse` 暴露 `segment_count`，前端以此为准。
- `.gitignore` 补充 `.pytest_cache/`、`*.log`、`*.db-shm`、`*.db-wal`。

## Out of scope
- 删除历史里已有的重复会话（属于数据操作，需单独确认）。
- 把已跟踪的日志/WAL 从 git 索引里移除（要动索引，单独确认）。
- README / docs 重写、novel.db 清理策略、鉴权、连接池、LLM 客户端复用。

## Constraints
- Must not change: 现有 HTTP 路径与响应字段的语义（只新增字段）、`Command(resume=...)` 的取值约定、审核阈值与驳回逻辑。
- Must not add: 新的第三方依赖。
- Must follow: 现有「一个功能一个函数」的组织方式；测试用临时库，绝不写 `novel.db`。
- 流式（SSE 逐 token）能力必须保持可用。

## Acceptance criteria
1. 真实调用一次较长输出后，`tokens.log` 中该条的 input ≤ 1 万且与 prompt 规模量级一致 — verified by 真实 API 调用一次并读日志。
2. 单元测试：给定「每个分片都带相同/累计 usage」的假流，记录值为**最后一个分片**的用量而非求和 — verified by `pytest tests/test_token_savings.py`。
3. `POST /api/sessions/{id}/resume` 在并发第二次调用时返回 409 — verified by `pytest`（TestClient）。
4. 侧栏「新建/续写/选择」在等待期间不可点击 — verified by App.vue/SessionSidebar.vue 静态断言 + `npm run build`。
5. 上传 `../../evil.txt` 时保存路径仍在 `knowledge_base/` 内（或直接拒绝）— verified by `pytest`（TestClient + 临时目录）。
6. 已有 6 段剧情时，「回退」仍可用，直到累计回溯 5 次 — verified by `pytest`（直接调用 `handle_backtrack`）。
7. `transform_graph_events` 对嵌套 runnable 不产生 node_start，对 6 个图节点产生事件 — verified by `pytest`（合成事件流）。
8. 响应含 `segment_count`，且前端用它更新「段落」计数 — verified by `pytest` + 静态断言。
9. 全量 `pytest` 通过且 `npm run build` 通过 — verified by 命令输出。
